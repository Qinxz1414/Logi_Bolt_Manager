# 2026-10-29

## logi bolt manager 项目整理

- 背景：目录原名 `源码/`、`补丁/`、`BoltManager/`（PyInstaller one-folder 产物），无 README、无版本控制。
- 项目的实际内容：Windows GUI 小工具（tkinter），基于**打过补丁的 Solaar 1.1.20**，列出 Logi Bolt 接收器
  （`046D:C548`）上的配对设备并支持解除配对。
- 整理后结构：`src/`（bolt_manager.py、gen_icon.py、bolt.ico、BoltManager.spec）、
  `patches/`（按 site-packages 结构摆放 4 个补丁文件）、`tools/`（rebuild / apply_patches / solaar-cli）、
  `dist/BoltManager/`（打包产物）、`docs/技术说明.md`、根 `README.md`、`.gitignore`、`.gitattributes`。
- 修改的配置：`BoltManager.spec` 去掉了硬编码的 `.../python/versions/3.13.12/hidapi.dll`，改为由 `SPECPATH`
  与 `sys.base_prefix` 推导；`rebuild.cmd` 改为在项目根目录调用 spec 并显式指定 `--distpath/--workpath`；
  `solaar-cli.cmd` 去掉硬编码 python 绝对路径。
- 校验：`python src\bolt_manager.py --list` 读到槽位 3（Alto Keys K98M Plus）、槽位 4（MX Master 3S）；
  用 `--distpath build/_verify_dist` 试构建成功且新 exe `--list` 退出码 0（验证产物已删除）。
- git：已 `git init`，3 次提交；`dist/`、`build/` 被 gitignore（exe 不入库）。
- 关键事实备查：Bolt 接收器在 `MI_02` 上暴露 Col01（仅短报文 0x10）与 Col02（仅长报文 0x11），
  Windows 严格校验长度，故补丁用 `_BoltSplitHandle` 虚拟双句柄；另有固件怪癖「长寄存器读 0x83 要用短报文发」；
  `SOLAAR_SOFTWARE_ID` 固定 `0x0B`；`base.py` 还含 Centurion（0x50/0x51、64 字节帧）传输支持。

## 开源化改造（第二轮，同日晚）

- 修正了第一轮文档的错误归因：`BoltReceiver`、Centurion、`SOLAAR_SOFTWARE_ID=0x0B` 都是 Solaar 1.1.20 上游自带；
  本项目真实补丁只有 4 个文件、+138/-3 行（hidapi 双集合虚拟句柄 + 3 个一行修复）。
- 补丁改为标准 unified diff（`patches/*.patch`，git apply 可消费），配 `tools/apply_patches.py`
  （应用/--check/--revert，强制关 autocrlf，撤销后与上游逐字节一致）与 `tools/make_patches.py`（可再生成）。
  补丁文件头加 GPL-2.0 §2(a) 要求的 MODIFIED FILE 声明。
- 法务：LICENSE（GPL-2.0 全文）、THIRD-PARTY-NOTICES.md、商标声明、二进制分发须附源码的说明。
- 代码：bolt_manager.py 加 `__version__`/`--version`/`--json`/`--debug`，数据层改返回 dict，
  设备名/序列号去尾部填充空格；gi 桩**不能**设 `__path__`（会让 solaar 的 find_spec 探测误判 GTK 可用而炸）。
- 关键发现 1：pip 装 solaar 在 Windows 会因 PyGObject 构建失败 → 必须 `pip install --no-deps solaar==1.1.20`
  再补 PyYAML/psutil/typing_extensions（logitech_receiver 实际只依赖这两个 + typing_extensions）。
- 关键发现 2：hidapi.dll 不在 pip 包里，是手工放进 Python 目录的 → 新增 `tools/fetch_hidapi.py`
  （官方 release + sha256 校验 → build/hidapi/），spec 与运行时（os.add_dll_directory，PATH 无效）都指向它。
- 验证：全新 venv 从零装依赖 → 打补丁 → 藏起手工 DLL → `--list` 读到 2 台设备，全链路可复现；
  `tools/verify_patches.py` 无硬件自检 5 项全过；ruff 全绿；最终 exe `--version/--list` 正常。
- CI：`.github/workflows/ci.yml`（windows-latest：依赖→补丁→自检→ruff；tag 触发打包，
  Release zip 附 LICENSE/THIRD-PARTY-NOTICES/patches 满足 GPL 源码可得）。
